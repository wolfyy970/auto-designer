# Design quality

Apply when shaping the visual and structural quality of a static-page artifact (HTML/CSS).

## Design-system precedence

When a design system is provided, it binds. Use its tokens, type scale, color roles, spacing rhythm, and component tone — stay within those bounds. Where the system is silent on a specific concern, the defaults below apply. Never introduce a second, conflicting visual system.

## The quality lens

- **Typography.** When no type system is provided, pick fonts that fit the design's intent. Treat scale as intentional (heading vs body vs caption), and let weight, line-height, and tracking carry hierarchy.
- **Icons.** Prefer Lucide over emoji or generic shapes — Lucide reads as polished and intentional. When the design system's aesthetic calls for a different icon style (sketchy, hand-drawn, ornamental, custom-illustrated), match that instead.
- **Color.** When no palette is provided, choose one that fits the design's intent — bold or muted, saturated or restrained, depending on what the design argues for. Coherence matters: use color to carry hierarchy (e.g., a dominant role with accents, or a strict monochrome with one accent), not as decoration distributed at random. Temperature and saturation carry meaning — clinical, saturated, muted, celebratory each argue different positions.
- **Spatial composition.** Intentional layout. Asymmetry, overlap, generous negative space, or controlled density — pick what serves the design's intent. Break predictable grid patterns when breaking serves the design; hold rhythm when restraint serves it.
- **Motion.** Match the design's character — a slow fade for calm presence, a snappy spring for urgency, stillness when the design is about restraint. Use `animation-delay` for staggered entrance when it argues the design.
- **Depth and atmosphere.** Apply depth (layered gradients, textures, patterns, dramatic shadows) when atmospheric character suits the design. Apply flatness (solid fills, no elevation, hierarchy via stroke and spacing) when provisionality, sketch, or brutalism is the design. Choose deliberately; both are valid.
- **Content tone.** Match the design's intent. Placeholder or lorem ipsum reinforces provisionality (drafts, wireframes, draft-for-discussion artifacts); realistic, plausible content reinforces credibility (finished UI, product mocks, polished prototypes). Don't mix the two.

## Checklist (every artifact)

- Typographic scale is intentional (heading vs body vs caption), not the browser default.
- Spacing rhythm is consistent (e.g. 4 / 8 / 12 / 16 / 24px steps) — don't randomize.
- Primary actions visually dominate; secondary actions are quieter.
- Above the fold: headline + supporting line + primary CTA within the first viewport when the design rewards that pattern.
- Mobile-first density; one primary task per screen.
- Use CSS custom properties for key tokens (color, type, spacing) when no design system is supplied.
- Fully responsive — mobile + desktop.
- **Every interactive widget is styled.** Buttons, inputs, textareas, selects, radios, checkboxes, fieldsets, labels — none of them shows browser defaults. Browser-default form elements bleeding through is the unmistakable signature of an unfinished prototype and is never acceptable.
