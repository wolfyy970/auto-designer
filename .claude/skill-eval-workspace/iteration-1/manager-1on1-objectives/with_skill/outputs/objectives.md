The design should be usable from a cold start — meaning a manager who opens it 15 minutes before a 1:1, with no prior session of preparation, can begin from what is already on the screen rather than from a blank field or a setup prompt. What the manager needs (recent context about this report, possible angles to take, something to react to) should be visible on first paint, not assembled by the manager from scratch. The failure mode to avoid: a design so eager to pre-fill that it presents inferred content as authoritative, putting words in the manager's mouth or anchoring the conversation around a machine-generated agenda the manager would not have chosen.

Any framework, prompt set, or structural scaffolding the design offers should be presented as material the manager can pick up, modify, or ignore — visibly optional rather than visibly required. The manager should be able to tell from inspection that nothing on the screen is graded, tracked for compliance, or expected back. The failure mode to avoid: optionality so total that the design provides no point of view at all, leaving the new manager (who came here precisely because they don't know what good looks like) staring at a neutral surface with no signal about what to try first.

The design should remain usable when the manager has done nothing to maintain it between 1:1s. No streak to keep, no fields that decay into staleness when skipped, no nag states that punish absence. A manager returning after three weeks of skipping should find the artifact in roughly the same shape as a manager who used it yesterday. The failure mode to avoid: a design so commitment-free that it cannot accumulate any value across sessions — every prep moment starts fresh because nothing the manager did before is reachable from where they are now.

The design should differentiate visibly across report types — what is shown for a 1:1 with a newcomer in their first 90 days should look different from what is shown for a 1:1 with a senior IC or a peer-turned-report — without requiring the manager to classify the report through a profile form, tag system, or upfront wizard. The differentiation should read as the design having noticed something about this person, not as the manager having configured a setting. The failure mode to avoid: differentiation that solidifies into stereotype, where the design's read of "senior IC" or "newcomer" becomes a label the manager has to override every time the actual person on the call doesn't fit the bucket.

The design should reveal its core value within the prep window itself — the 15-to-30-minute moment the brief names — rather than requiring weeks of accumulated use before the manager can tell whether it is worth keeping. A first-time opener should be able to leave the first session with something they would take into the 1:1, not just an investment in future sessions. The failure mode to avoid: front-loading the prep moment with so much immediate output that the manager spends the window reading what the design produced instead of thinking about the person they're about to meet.
