The surface should produce a documentation checklist that is specific to the user's destination state, residency status, and personal situation (REAL ID upgrade, name mismatch across documents, non-citizen with visa caps, recent gender-marker change) before the user leaves home for the DMV. The failure mode to avoid: a checklist confident enough that the user trusts it and arrives at the counter, only to discover the state has a wrinkle the surface didn't catch — false confidence is worse than no checklist.

The experience should communicate what the in-person visit will actually feel like at the user's local office — the documents they will hand over, the order things happen, the wait pattern this particular branch is known for — so the user can decide when to go and what to expect. The failure mode to avoid: overconfident specifics ("be out by noon") that the local DMV's reality will not honor, eroding the surface's credibility on the first visit.

The surface should treat the license transfer as one task in a larger move, not as the user's sole concern. It should hold low-frequency attention, let the user step away and return without losing context, and avoid behaviors that demand the kind of sustained engagement the rest of the move is already consuming. The failure mode to avoid: a surface that gets the right answer but at a cost of attention the user does not have to give it.

The temporary-license window — paper printout to hard-copy delivery — should be explained in terms of what the user can and cannot do with the temporary form: fly domestically, open a bank account, pass a background check, prove residence. The failure mode to avoid: silent ambiguity that leaves the user discovering the temporary's limits at an airport or a bank.

When the user's situation falls outside what the surface can handle confidently (an unusual immigration status, a name-change with documents from a non-US jurisdiction, a contested out-of-state record), the surface should route the user out to the right human help rather than guess. The failure mode to avoid: a confident wrong answer in the cases where the user most needs the system to admit its limits.
